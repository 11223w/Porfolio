Click And Sip Cafe

Overview

Customers register and log in, browse the menu, add drinks to a cart and place an order. The order is saved in the database with an invoice number, then the customer chooses Cash or GCash.

  • PHP
  • MySQL
  • HTML, CSS, JavaScript
  • XAMPP

Source and our part

The original source code was provided by a group member's cousin. We reviewed it, fixed the problems listed below, wrote the README and test cases, and prepared it to run on XAMPP. AI was used to help with the fixes (see the AI Log).

Features

  • Registration with checks: no empty fields, valid email, password of at least 6 characters, no duplicate username or email
  • Login and logout with a session; the shop and payment pages need a login
  • Menu with a cart: add items, change quantity, remove items, live total
  • Orders saved to the database, one invoice per order, linked to the logged-in user
  • Payment page for Cash or GCash, saved against the order

My contribution

I suggested the web app idea for this project: an online ordering website for a coffee shop, with login, a cart and payment. The group then reviewed, fixed and documented the code together.

Fixes, Testing and Limits

Problems we fixed

  • The database script had errors and could not be imported, so it was rewritten.
  • The payment code used a table name that did not exist.
  • Orders were not saved properly, and every payment went to order number 1. Each order now has its own invoice, and the amount is calculated again on the server.
  • Login and registration were open to SQL injection and stored passwords with MD5. They now use prepared statements and password hashing.
  • Menu images used the wrong folder, and one image was missing.
  • Google sign-in was removed because its library was not included, along with some unrelated practice files.

Testing and limits

Testing: 11 test cases are written in the README (register, login, wrong password, protected pages, empty cart, order, Cash, GCash, logout). Pass or Fail results will be recorded after running them on XAMPP.

Limits: item prices come from the web page, not from a products table; there is no admin page, order history or email confirmation; and it needs PHP and MySQL, so it cannot run on GitHub Pages.
